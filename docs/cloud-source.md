# 云端底图（gpt-image-2 等）

界面上多了两个风格预设：**API 底图 · CHORD 分解** 和 **API 底图 · 手绘派生**。
它们把"出底图"这一步交给云端模型，**PBR 分解仍然全程在本地跑**。

## 定位：补充，不是替代

云端模型对提示词的理解明显强于本地 SDXL，但在纹理这件事上它有几处硬伤：

| | gpt-image-2 | 本地 SDXL + SeamlessTile |
|---|---|---|
| 真无缝 | ❌ 接口里根本没有这个概念 | ✅ 循环卷积，实测 3×3 零接缝 |
| 种子复现 | ❌ 不支持 | ✅ 严格复现 |
| 图内文字 / 符号 | ✅ 断层领先 | ❌ 基本不可用 |
| 单张分辨率 | ✅ 最高 2880²  | ⚠️ 1024² 原生 |
| 单张耗时 | ❌ high 档 150~235 秒 | ✅ 全链路 35~60 秒 |
| 单张成本 | ❌ high 1024² 约 $0.13~0.22 | ✅ 电费 |
| 内容审核 | ❌ 有，关不掉 | ✅ 无 |
| 网络 | ❌ 大陆需代理 + 组织验证 | ✅ 离线可用 |

所以它值得用的场景就两类：**纹理里要有清晰的文字/符号/纹章**（刻字石碑、招牌、
带铭文的装饰面），以及**需要一次拿到 2K 以上的高细节底图**。日常量产可平铺材质，
本地那两条管线在成本、速度、可控性上全面胜出。

## 为什么不用 ComfyUI 自带的 API 节点

ComfyUI 有官方的 `OpenAIGPTImage1` / `OpenAIGPTImageNodeV2` 节点，但它们调的是
`/proxy/openai/...`，鉴权走 `auth_token_comfy_org`——**花的是 comfy.org 账号里的
积分，不是你自己的 OpenAI key**。官方文档明说目前不支持用自己的 provider key。

对一个单机工具来说，让用户为了一个可选功能去注册 comfy.org、用 Stripe 充值，
还得让 ComfyUI 能出外网，代价太大。而且错误会埋在工作流执行里：余额不足、审核
拒绝、429 限流，多半都表现为"某个输出分支缺失"，我们只能报"少了张图"，给不出
"你的组织没做身份验证"这种能照着办的提示。

所以走 Go 后端直连。底图拿回来之后，对本地管线而言它就是一张普通输入图。

## 一条管线，两种形态

两个 API 预设都有一个**无缝重整**滑块，它决定整条图长什么样：

```
             ┌─ 无缝重整 = 0 ─────────────────────────────┐
云端底图 → 缩放 ┤                                      → CHORD / 亮度推导 → 各通道
             └─ 无缝重整 > 0 ─→ VAE编码 → SDXL重绘 → 解码 ┘
                                （循环卷积，让边缘可平铺）
```

- **大于 0**：本地 SDXL 用循环卷积把它重画一道，换来真正可平铺。数值越大越无缝、
  也越偏离云端原图，0.35~0.55 通常够用。
- **等于 0**：直接分解，**产物不保证可平铺**。好处是整条 SDXL 支路会被从节点图里
  删掉，所以**不下 7GB 的底模也能用**。

这不是靠两份模板实现的，而是模板声明里的一对条件规则：

```json
{ "key": "tile_fix", "type": "float", "min": 0, "max": 0.85,
  "target": "dt.sampler.denoise", "default": 0.45,
  "rewire_when_zero": [
    { "node": "dt.pbr_estimate", "input": "image", "source": "dt.source_scale", "slot": 0 },
    { "node": "dt.out.source",   "input": "images", "source": "dt.source_scale", "slot": 0 }
  ],
  "drop_when_zero": ["dt.checkpoint", "dt.seamless_model", "dt.seamless_vae",
                     "dt.positive", "dt.negative", "dt.sampler", "dt.decode", "dt.source_encode"] }
```

删而不是留着：留着的话 ComfyUI 仍然会去校验 `CheckpointLoaderSimple`，于是没下过
底模的人光想用云端也会被拦住。改接必须排在删除之前，否则要找的源节点已经没了。

条件删除很容易漏掉一条下游引用，而 ComfyUI 那边的报错是 `Node ID '#9' not found`
——既不说谁引用的，也不说那节点原本是什么。所以 `Render` 结束前会扫一遍悬空连线，
用模板里的标题把话说清楚。

## 暗角必须消掉，否则平铺一定出网格

**这是接入云端底图时最要命的一条。** GPT image 系列有从中心到边缘的亮度衰减，
单看一张图很自然，一旦平铺，四个瓦片的暗边拼在一起就是一张可见的网格——纹理
最忌讳的就是这种规律性痕迹。本地 SDXL 走循环卷积不存在这个问题。

`internal/imagen/flatten.go` 的做法是拟合一个低阶二维多项式当作亮度场，然后把图
除以它。这里有两个实测撞出来的坑，都记在代码注释里：

**一、不能用大半径高斯模糊当亮度场。** 最初的实现是三趟带边缘延拓的盒式模糊逼近
高斯。问题是每一趟都会把边界值往内部均值拉一点，三趟下来边界基本被洗白——512 见方
的图上只还原了三分之一的暗角（场的边缘/中心比 0.919，真实值 0.757），**恰恰在最
需要校正的四条边上最不准**。多项式是全局拟合，边界取值由整体趋势外推，没有这个问题；
另一个附带好处是 4 阶多项式根本没有表达高频的自由度，想吃掉纹理细节也吃不动。

**二、不能在 log 空间拟合。** 暗角是乘性的，取对数变成加性，看着更该那么做。实测
反过来咬人：log 拟合估的是几何均值，而几何均值会被局部方差压低，于是"花纹多、明暗
跳动大"的区域被误判成"暗"，去校正它就等于凭空提亮。有多离谱——一张完全没有暗角的
合成图（边缘/中心 0.987）过完 log 版之后变成 0.81，**这一步自己造出了一圈暗角**。
改成线性最小二乘（估的是局部算术均值）之后才对。

压平是归一化到**均值**，所以重暗角的图会中心稍压暗、边缘提亮，整体亮度不变。

**校正的靶子是纹理自身的比值，不是 1.0。** 这条是被实测逼出来的：端到端跑通那次
看到 0.7509 → 1.0485，第一反应是过冲了 5%，查下去才发现那张测试纹理**自身**的
边缘/中心比就是 1.0541（它的正弦周期在采样窗口里不整除），校正后离它的固有值
只差 0.7%。拿 1.0 当靶子会两头出错：既会把"纹理本来就不匀"误判成算法有毛病，
也会诱使人去多校正一点，把真实结构抹掉。

实测（`internal/imagen/flatten_test.go`、`flatten_srgb_test.go` + 6 张本机真实素材）：

| 输入 | 边缘/中心（前 → 后） | 该纹理自身的值 |
|---|---|---|
| 合成纹理 + 0.15 / 0.30 / 0.45 暗角（线性空间） | 0.906 / 0.830 / 0.753 → 0.980 | 0.982 |
| 合成纹理 + 0.15 / 0.28 / 0.45 暗角（sRGB 空间） | 0.886 / 0.754 / 0.600 → 1.047 | 1.054 |
| 真实素材 ×6 + 0.22 暗角 | 0.83~0.91 → 0.98~1.05 | 0.99~1.03 |
| 本地 SDXL 原图 ×6 | 0.99~1.03，判定「不必动」，原样返回 | — |

两种暗角模型都验了：线性空间乘（物理正确）和 sRGB 空间乘（真实模型输出更接近这种，
两者不等价，sRGB 上乘 g 相当于线性上乘约 g^2.2）。

细节保留：压平相对"打了暗角之后"的图只损失 0.2%~0.6%，那是一次 8 位重新量化的
代价，不是模糊。高光没有被顶到 255（截顶像素 0）。阈值 0.98 以内不动手——肉眼
看不出来，动它只会平白多一层重采样。

manifest 里记的 `falloff_after` 与**落盘 PNG 实测**的偏差在 0.0005 以内：报告值是
从内部浮点数组算的，中间隔着一次 8 位量化，所以专门验了一遍两者对得上——
写进 manifest 的数字要是和文件对不上，那比不记还糟。

## 关键约束（都在 Go 侧先校验，不让你等一趟往返才收 400）

**尺寸**：两边必须是 16 的倍数、长边 ≤ 3840、宽高比 ≤ 3:1、总像素在
655,360~8,294,400 之间。推论是**正方形上限 2880×2880，4096² 拿不到**；4K 只在
非正方形下成立（3840×2160）。

**提示词**最长 32,000 字符。模板的前后缀会一并送出去——CHORD 依赖那段平光约束，
丢了会把烘焙进底图的阴影当成真实起伏。

**刻意不传的两个参数**：`response_format` 对 gpt-image 系列无效（它固定返回
base64）；`input_fidelity` 在 gpt-image-2 上明确不允许改（它一律按高保真处理输入图），
传了会被拒。

**`moderation` 设为 `low`**。纹理素材经常出现"石头裂缝""血迹""锈蚀"这类词，
默认档容易误伤。这是官方支持的取值，不是绕过审核——low 档仍然拦真正的违规内容。
审核拒绝会以独立的错误形态浮上来，提示改说法或改用本地管线。

## 复现性：manifest 不撒谎

云端接口不支持种子，同样的提示词每次结果都不同。manifest 里因此多了一个
`source` 字段，**它一出现就意味着这份材质复现不了**：

```json
"source": {
  "provider": "openai", "model": "gpt-image-2",
  "prompt": "texture of ... , flat even lighting, no shadows",
  "size": "1024x1024", "quality": "medium",
  "input_tokens": 52, "output_tokens": 1568,
  "cost_usd": 0.0473, "elapsed_ms": 24310,
  "flattened": true, "falloff_before": 0.912, "falloff_after": 0.981
}
```

没有另加"可否复现"的布尔量：老素材没有 `source` 字段，天然读成"本地、可复现"，
不需要迁移。manifest 里的 `seed` 仍然是真实的——它作用于本地重整那一半，界面上
也因此改叫「本地重整种子」。

`tileable` 是**按次算的**，不是模板上那个静态值：同一份模板，无缝重整开了就是
`true`，调到 0 就是 `false`。这个字段是给三维预览和 UE 用的，报错了就是骗下游。

花费一律取服务端回报的 `usage`，不用任何第三方报价表估算。界面上提交前显示的
是量级参考（$0.01 / $0.05 / $0.13~0.22 一张），素材详情里才是真实花费。

## 自定义接口地址

**在「模型 → 设置」里改，不用重启后端。** 填成兼容网关的地址（自建中转、Azure、
第三方代理）即可，留空恢复官方。保存时后端会立刻探一次连通性，地址写错当场就能看到，
不必等到点生成。

优先级是 **设置页 > 配置文件的 `imagen.openai_base_url` > 官方地址**。

有三个细节是刻意这么做的：

**地址存在 `secrets.json`，不在普通配置里。** 第三方网关经常把密钥直接嵌在路径里
（形如 `https://gw.example.com/sk-xxxx/v1`），当成普通配置存就会跟着仓库一起泄出去。
放进凭据文件它自动获得 0600 权限和 gitignore。

**接口只回传 origin，不回传完整地址。** 界面上要让你确认"我现在指着官方还是自己的
网关"，但完整地址不能回传，理由同上。所以设置页显示的是
`当前指向 gw.example.com（自定义）`。

**报错时说的是实际主机名。** 用了网关之后再报"连接 OpenAI 超时"会把人往错方向带，
所以超时、解析失败、拒绝连接、证书错误这几类都会带上真实主机名；自检那一行也会
显示 `可达，4 个图像模型可用（312ms，经 gw.example.com）`。

换网关会让模型缓存立刻失效——不同网关暴露的模型不一样，拿旧清单去选会选出对面
没有的模型。

## 配置

```jsonc
"imagen": {
  "proxy": "",              // 优先于 HTTPS_PROXY 环境变量
  "openai_base_url": "",    // 设置页没填时的兜底地址
  "flatten": 1              // 亮度场压平强度 0~1
}
```

**`proxy` 这个出口是必要的。** 后端若以服务或计划任务方式启动，拿到的是另一套
环境，读不到你终端里的 `HTTPS_PROXY`；而 `api.openai.com` 在部分网络下只能经代理
访问，配不上的症状是干等到超时，很难一眼看出原因。所以网络层错误都补了排查方向，
自检里也单列了一条「云端底图」，启动就能看出通不通，不用等提交任务卡上几分钟。

**不内置任何第三方中转商地址。** 那等于替你决定把令牌和图交给谁。要用自己填。

## 令牌

在「模型 → 设置」里填，存在 `configs/secrets.json`（0600，已 gitignore）。
沿用既有的**只写不读**约定：接口只报告某个令牌"有没有设置"，永远不回传内容。

三件事需要分别满足，缺一个都用不了：

1. **令牌本身** —— platform.openai.com/api-keys
2. **组织身份验证** —— 图像模型强制要求。未验证时报
   `Your organization must be verified to use the model 'gpt-image-2'`，
   去 platform.openai.com/settings/organization/general 办，需要政府签发证件，
   通过后最多 15 分钟生效。**中国大陆不在支持的国家/地区列表内**，这与网络是
   两件独立的事。
3. **网络能到** —— 见上面的 proxy

## 模型清单不写死

可用模型是现问 `/v1/models` 的，按你的令牌实际权限列出。写死一份清单迟早过期：
新模型发布时用户明明有权限、工具却不认；下架的老模型又一直挂着（dall-e 系列已于
2026-05-12 从 API 下线）。

内置的那张表只决定**标签和参数选项**，认识的模型标注速度/价格特点排在前面，
不认识的仍然给出来但标「未收录」，参数按 gpt-image 系列推定——这样你哪天开通了
新模型权限，工具当天就能用上，只是提示词之外的选项可能对不上。

已收录：`gpt-image-2`（旗舰）、`gpt-image-1.5`、`gpt-image-1`、`gpt-image-1-mini`（最便宜）。

## 排队策略：同步做，不预取

云端调用放在任务执行里同步完成，而不是提交时就预取。代价是这段时间 GPU 闲着；
换来的是**取消排队中的任务时钱还没花掉**。对单人单卡的本地工具来说这个取舍更重要。

一次提交 N 个变体就是 N 次云端调用，界面上提交前会把这个乘法明说。
注意 OpenAI 的 Tier 1 只有 5 IPM（每分钟 5 张），变体开太多会撞限流。

## 端到端实测（2026-08-27，本机）

没有真实令牌也能验整条链路：`tools/fake_openai.py` 是一个 OpenAI 图像接口的兼容桩，
出图时故意打上 0.28 的径向暗角（真实模型就是这个毛病）。把接口地址指向它，整条路
就跑起来了——这也正好把"自定义 base URL"这个功能一起验了。

```bash
python tools/fake_openai.py          # 监听 127.0.0.1:8899
```

然后在设置页把令牌填成任意非空串、接口地址填 `http://127.0.0.1:8899/v1`。

                      来源 openai / gpt-image-2

## 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /api/imagen/providers` | 各来源的可用性与模型清单（现问服务端，可能慢到一秒） |
| `GET /api/settings` | 多了 `token_providers`：令牌来源的标签、申请指引、当前接口地址的 origin |
| `POST /api/settings/endpoint` | body `{provider, base_url}`，留空恢复官方；返回 origin 与连通性探测结果 |
| `GET /api/checks` | 有工作流声明了云端来源时，多一条「云端底图」自检 |
