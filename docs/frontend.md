# 前端说明（M2）

Vue 3 + Vite + TypeScript + Naive UI。构建产物嵌进 Go 二进制，最终交付仍是一个 exe。

## 跑起来

日常使用不需要单独跑前端——`bin/dreamtexture.exe` 里已经带着界面，
启动后浏览器打开 `http://127.0.0.1:8777` 即可。

改前端时用开发服务器，接口与 WebSocket 都代理到后端，改完即刷，不用重启后端
（重启后端要等 ComfyUI 重新安定，一次两分钟）：

```bash
cd web && pnpm dev
```

改完重新构建并嵌入：

```bash
cd web && pnpm build && cd .. && go build -o bin/dreamtexture.exe ./cmd/dreamtexture
```

Vite 的 `outDir` 直接指向 `internal/web/dist`，省掉一步拷贝。仓库里留了一个占位
`index.html`，保证没构建过前端时 Go 也能编译。

## 页面

| 路由 | 内容 |
|---|---|
| `#/generate` | 生成台：参数表单、变体数、实时队列与出图 |
| `#/library` | 素材库：搜索、风格筛选、只看收藏 |
| `#/material/:id` | 素材详情：3D 材质预览 / 通道检视、元信息、参数回填 |
| `#/models` | 模型管理：缺失检测、下载、磁盘占用 |
| `#/workflows` | 工作流：往返编辑、导入、在 ComfyUI 里打开 |
| `#/nodes` | 节点：搜索安装 7757 个节点包 |
| `#/console` | 控制台：后端与 ComfyUI 的实时日志、ComfyUI 启停 |
| `#/settings` | 设置：访问令牌、网络、云端底图、ComfyUI 环境、一键部署 |

导航里控制台和设置与前五项之间隔了一道细线：前面五个是干活的地方，
后面两个是看和调的地方。一条线比多一级菜单轻。

**令牌从模型页挪到了设置页。** 令牌、代理、环境路径这些是全局性的东西，
散落在各功能页里就得靠记忆去找；模型页只管模型本身。

生成台顶部还有一条**环境自检横幅**，只在有问题时出现：ComfyUI 不通、节点没注册、
模型缺失、输出目录不可写。同类工具最大的劝退点是装不上跑不起来，而报错往往等到
点了生成才出现——与其让用户对着一句 `node not found` 发愣，不如进门就说清楚缺什么。

## 关键设计

**表单完全由后端 schema 驱动。** 前端不认识任何具体参数名——控件从
`GET /api/workflows` 返回的 `params` / `advanced` 声明生成，有上下界的数值给滑条，
枚举给下拉，长文本给多行框。工作流加一个可调项，界面自动就多一个控件，不用改前端。

**提示词的前后缀如实展示。** 模板会固定追加一些不该让用户删掉的约束
（例如 CHORD 需要的平光描述），输入框下方原样显示拼接后的完整提示词，
用户能看到真正送进去的是什么。

**换预设保留已改过的值。** 切风格不该把写好的提示词冲掉；但没动过的参数仍跟随
新预设的默认值——两条管线的派生参数差别很大，一股脑带过去反而出坏结果。

**日志走轮询，不走 WebSocket。** ComfyUI 采样时会刷出大量进度行，逐条推进事件流
等于把它当日志管道用，正经的任务事件反而可能被挤掉。轮询天然合批，界面上看着
一样是实时滚动。客户端带 `since` 游标增量拉；服务端序号倒退就说明后端重启过，
把本地缓存清空重来。

**自动跟随只在已经贴着底部时生效。** 正在往回翻历史时被拽到底部很烦人。

**设置项的说明文字是必填的。** 设置最常见的失败不是控件难用，而是用户看着标题
猜不出改了会怎样，于是不敢动。需要重启才生效的项直接在标题旁标出来，
别让人改完以为已经生效了。

**平铺预览是验收工具不是装饰。** 无缝是硬指标，而接缝只有拼起来才看得见，
所以详情页每个通道都能 1×1 到 4×4 平铺检查，另有像素级放大用来看噪点和压缩痕迹。

预览区一律按 `clamp(320px, 52vh, 560px)` 收敛高度。早先用 `aspect-ratio: 1`，
在宽列下会撑出上千像素高、必须滚动才看得全，反而没法整体判断接缝。

## 3D 材质预览

逐张看通道图判断不了材质好坏——法线对不对、粗糙度分布合不合理，只有在光扫过
表面时才看得出来。所以详情页默认进 3D 预览（Three.js），通道检视作为并列的另一档。

**兑现了 manifest 的 `normal.y` 字段。** 我们的管线统一输出 DirectX(Y−) 法线，
而 three 按 OpenGL(Y+) 解释——组件读 manifest 的 `y` 字段决定 `normalScale.y` 取
`-1` 还是 `1`。不必为了迁就预览去改变产物本身：UE 才是主消费方。

**光照可调，而且这是重点。** 初版只给了一束固定的转动光，环境光还给到 0.55，
把方向光完全冲淡了，看不出任何表面细节。现在暴露光强、高度角、环境光、色温四项，
外加三档预设：

| 预设 | 用途 |
|---|---|
| 掠射 | 高度角 12°、环境光 0.18 —— 看法线与高度细节的主力 |
| 柔和 | 高度角 45°、环境光 0.7 —— 看整体色调 |
| 强反差 | 光强 6.0、环境光 0.05 —— 挑粗糙度分布不匀的地方 |

实测三档在画面上的差异（中心区亮度统计）：柔和均值 202、标准差 26；掠射均值 144、
标准差 32、最暗到 9；强反差最暗到 7。**掠射的局部反差最高，正是它显露表面细节的原因。**

其余：几何体可切平面 / 球体 / 立方体（平面细分 320×320，置换才不呈阶梯状）、
平铺 1–4×、置换强度可调（球和立方体上减半，否则边缘会裂）。环境光用 three 自带的
`RoomEnvironment` 程序生成 IBL，不需要外部 HDRI 文件——PBR 没有环境光就是一坨死板的塑料。

**贴图一律衬中性深底。** 法线、粗糙度这些在浅底上看不清边界。

**没上 Pinia。** 全局状态只有任务表和 ComfyUI 健康两份，一个响应式模块
(`src/store.ts`) 就够，也少一层依赖的 API 变动风险。

## 视觉

**浅色是暖纸调，深色是中性近黑——这是刻意的不对称。**

最初深色也用暖色打底（褐黑 `#1A1611` 配褐灰），结果整片发浑发脏：低饱和的暖色
铺满大面积时读起来像蒙了层灰。改成中性近黑之后，暖琥珀反而成了画面里唯一的暖点，
identity 更清楚，也干净得多。**暖色留给强调色，不铺满底。**

| | 浅色 | 深色 |
|---|---|---|
| 底 | `#F6F2E9` | `#0E0E11` |
| 面 | `#FFFDF8` | `#16161A` |
| 字 | `#24201B` | `#ECECF1` |
| 强调 | `#A96F0E` | `#F2B04A` |

圆角：控件 6px，卡片 10px。够软化边缘，又不至于变成气泡。

### 导航：左侧栏，可收起

左栏固定不滚，右侧内容自己滚——**整页只有 `.body` 一个滚动容器**。
展开 210px，收起 60px（只留图标，悬停出 tooltip）。收起状态记在 localStorage。

分成两组：上面五项是每天都点的（生成台/素材库/工作流/节点/模型），
底部两项是偶尔进去看一眼、调一下的（控制台/设置），下面一条细线，
再往下是 ComfyUI 状态、外链、主题开关、收起按钮。挤成一列的话最常用的
入口反而被稀释了。

几个踩过的点：

**侧边栏不用毛玻璃。** `backdrop-filter` 要底下真有东西滑过才成立，
而固定不动的左栏后面什么都不会经过，只会变成一块半透明色。

**宽度过渡放在 `.side` 自己的 `width` 上，不要去过渡 `grid-template-columns`。**
最初写成 `grid-template-columns: var(--side-w) ...` 再改变量，结果宽度总是慢一拍：
类已经切了、宽度还停在上一态。自定义属性的变更与依赖它的属性过渡解析次序对不上，
过渡两端拿到的是同一个旧值。

**高度用 `100vh` 而不是 `100%`。** `.shell` 外面套着三层 naive-ui 的 Provider，
只要其中任何一层没撑满高度，`height:100%` 就落空——侧栏塌成内容高度，控制台那个
`100vh` 再一叠就把整页顶出屏幕。

**收起时每一处标签都要自己 `overflow: hidden`。** 宽度收到 0 但不裁剪的话，
文字照样溢出来；外层的 `overflow:hidden` 只在最后一刻挡住它，宽度过渡的那 0.22 秒
里还是会看见字压在图标上。

**localStorage 里的偏好要同时把"用户表过态"记下来**，否则挂在 `onMounted` 上的
窄屏自动收起会立刻把它覆盖掉——"记住收起状态"就成了摆设，而且没有任何报错。

### 版面：三档宽度，一律居中

所有页面共用 `.dt-page` 外壳，宽度只有三档，按内容形态选：

| 档位 | 宽度 | 用在 |
|---|---|---|
| `dt-page-narrow` | 900px | 设置——表单行宽超过这个就不好读 |
| （默认） | 1120px | 工作流、节点、模型：列表 |
| `dt-page-wide` | 1440px | 生成台、素材库、素材详情：网格与两栏 |
| `dt-page-full` | 不限 | 控制台：日志行又长又密，越宽越少折行 |

左右留白 `clamp(16px, 2.6vw, 34px)`，上下 `clamp(16px, 2vw, 26px)`——13 寸笔记本上
34px 太奢侈，27 寸上 16px 又贴边。

**之前各页各写各的（1100 / 1040 / 1000 / 900，还有两个干脆没写）而且都没居中，
宽屏上内容全贴在左边、右侧空一大片。**

### 字号只留六档

`--dt-fs-2xs 10.5 / xs 11 / sm 12 / base 13 / md 14 / lg 20`。

之前是散着写的，全局数下来 13 种，其中 11 / 11.5 / 12 / 12.5 / 13 / 13.5 挤成
一团——**差半个像素的两档读起来不是层级，是没定过标准**。收成六档之后每一步都
看得出来，写新界面时也不必再"大概比它小一点"地猜。

### 页头统一

`PageHeader` 组件：标题 + 一句说明 + 右侧操作，底下一条细线。说明那句不是凑数的：
原先「节点」「模型」「工作流」几页只有一个光秃秃的标题，第一次进来得点开试试才
知道是干什么的——尤其"工作流"和"节点"在 ComfyUI 的语境里都容易望文生义。

控制台是唯一的例外：它的日志窗口要占满高度，再叠一个标准页头要吃掉六十多像素，
所以标题并进了那条状态栏。

### 其它

**卡片有一层极浅的投影**（`0 1px 2px var(--dt-shadow)`）。纯平的卡片在浅色主题下
几乎和背景融在一起，只靠 1px 边框撑着，读起来像线框图而不像面。

**键盘焦点有可见指示**。自己写的 a / button（导航项、顶栏幽灵按钮、模式切换、
部署面板折叠头）此前一个都没有，用键盘走一遍完全不知道停在哪。用
`:focus-visible` 而不是 `:focus`——鼠标点击不该冒出焦点框；用 `:where()` 把
优先级压到 0，组件想覆盖随时能覆盖。

**导航选中态只用一件事表达**：底色 + 强调色文字。原先底色之外还在下面挂了个小
圆点，两个记号说同一件事——两三个条目时不明显，加到七个之后整条导航就显得碎。

**`packageManager` 必须钉住。** 不钉的话 corepack 每次都把 pnpm 解析成最新版，
新版一发布就会判定依赖过期、要清空 `node_modules` 重装——而这套依赖是精确固定过的
（TypeScript 停在 5.9，vue-tsc 还不兼容 TS7），重装很可能换出不兼容的组合。
开发服务器也因此直接用 `node web/node_modules/vite/bin/vite.js web` 起，不经过 pnpm。

**毛玻璃**只用在浮于内容之上的层（顶栏、生成台的吸顶面板）。为此整页只留一个滚动
容器、顶栏 `position: sticky`——`backdrop-filter` 需要底下真有东西滑过才成立，
不然只是一块半透明色。不支持的环境按 `@supports` 退回不透明底色。

**动画**克制地用在三处：卡片入场（错峰上浮）、生成中的扫光（比空转的圈更能表达
"在算"）、悬停微提升。路由切换只做进入不做离开——离开动画会让点击后出现一段
"什么都没发生"的空窗，反而显得慢。全部在 `prefers-reduced-motion` 下关闭。

色板同时写进 CSS 变量（`--dt-*`），自写样式与 Naive UI 组件不会脱节。

## 踩到的坑

**vue-tsc 与 TypeScript 7 不兼容。** TS 7（Go 原生重写版）去掉了 `./lib/tsc`
子路径导出，而 vue-tsc 3.3.11 仍依赖它，尽管它的 peerDependencies 写着
`>=5.0.0`。工具链固定在 TypeScript 5.9.x，等 Vue 生态跟上再升。

**懒加载视图的 watcher 必须加 `immediate`。** 视图 chunk 到位时后端数据往往
已经拉好了，`watch(computed, cb)` 在注册前目标就已有值，不加 `immediate`
回调永远不触发——表现是表单一片空白，但控制台没有任何报错。

**别对异步加载中的贴图设 `needsUpdate`。** `TextureLoader.load` 是异步的，
改 `repeat` 时顺手标脏会刷一屏
`THREE.WebGLRenderer: Texture marked for update but no image data found`。
改 `repeat` 本来就会自动重算纹理矩阵，那行是多余且有害的。

**three 的对象要用 `shallowRef`。** 深度响应式代理一整个场景图既慢又容易出怪问题。

**teleport 出去的内容拿不到 scoped 样式。** Naive UI 的下拉菜单挂在 `body` 下，
而 scoped 编译成 `[data-v-xxx] .foo`，需要一个带作用域属性的祖先——teleport 出去
的节点没有。`:deep()` 也救不了，它改的是选择器后半段。所以凡是用 `render-label`
自定义的下拉项，样式必须放进全局表（`style.css` 里的 `.dt-opt-*`）。

选中态那一份在组件作用域内，倒是能生效——这恰恰是坑：只看关着的下拉框会以为
样式没问题，展开才发现菜单里是裸的。

**改了前端必须重新 `go build`。** 前端是 `//go:embed` 进二进制的，
`pnpm build` 之后不重编 Go 就还是旧界面，而且浏览器 hash 路由跳转不会重载 JS，
看起来就像改动没生效。
